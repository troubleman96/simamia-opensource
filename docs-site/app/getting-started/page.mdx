# Getting started

## Environments

| Environment | API base URL |
| --- | --- |
| Local Go service | `http://localhost:8080/api/v1` |
| Production | `https://api.simamia.online/api/v1` |

Browser users create local accounts through the Go API. Passwords are stored as salted PBKDF2-HMAC-SHA-512 hashes, and successful sign-in returns a random bearer token whose hash is stored by the API. Never send a password as the bearer credential.

## 1. Start the API locally

From the Simamia repository root:

```bash
cd api
go run ./cmd/simamia-api
```

The service listens on port `8080`; `PORT` changes the port. The default database path is `data/simamia.db` relative to the process working directory. Set `SIMAMIA_DB_PATH` to choose another location.

## 2. Check health

Health is public and does not need an access token:

```bash
curl --include http://localhost:8080/api/v1/health
```

Expected data includes service `simamia-api`, API version `v1`, timezone `Africa/Dar_es_Salaam`, and currency `TZS`.

## 3. Create an account and sign in

Account creation immediately returns a session. Use a unique phone number and a throwaway password in local development:

```bash
export SIMAMIA_API='http://localhost:8080/api/v1'
export SIMAMIA_TOKEN=$(curl -sS -X POST "$SIMAMIA_API/auth/register" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Asha Mushi","phone":"+255 712 345 678","password":"demo-password-2026","remember_me":false}' \
  | jq -r '.data.access_token')
```

To sign in to an existing account instead, send the same `phone` and `password` to `POST /auth/login`. `remember_me: true` issues a 30-day session; otherwise it expires after 12 hours. Use `GET /auth/me` to check the session:

```bash
curl --include "$SIMAMIA_API/auth/me" \
  -H "Authorization: Bearer $SIMAMIA_TOKEN"
```

## 4. Create your first records

Create a customer first. Then use its display name on the order; the current API stores the customer as a name string rather than a customer foreign key.

```bash
curl --include -X POST "$SIMAMIA_API/customers" \
  -H "Authorization: Bearer $SIMAMIA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Asha Mushi","phone":"+255 712 345 678","location":"Kinondoni, Dar es Salaam"}'
```

Create a service before using it in an order:

```bash
curl --include -X POST "$SIMAMIA_API/services" \
  -H "Authorization: Bearer $SIMAMIA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Wash and fold","category":"Laundry","duration":"24 hours","price":25000}'
```

Then create an order:

```bash
curl --include -X POST "$SIMAMIA_API/orders" \
  -H "Authorization: Bearer $SIMAMIA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"customer":"Asha Mushi","phone":"+255 712 345 678","service":"Wash and fold","date":"2026-10-12T09:00:00+03:00","amount":25000,"status":"New","paid":0,"method":"Not paid","assignee":"Owner"}'
```

Record IDs are generated by the server. Use the created response's `data.id` in follow-up requests. Every record is scoped to the local account ID that owns the session.

## 5. Create a Simamia business profile

`POST /businesses` stores the business profile created during app onboarding. The API currently accepts a JSON object without resource-specific required fields. Use your template ID in `primaryTemplate` and include a version for later workflow migrations.

```bash
curl --include -X POST "$SIMAMIA_API/businesses" \
  -H "Authorization: Bearer $SIMAMIA_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"businessName":"Amani Laundry","phone":"+255712345678","primaryTemplate":"laundry","templateVersion":1}'
```

When finished, revoke the session:

```bash
curl -X POST "$SIMAMIA_API/auth/logout" -H "Authorization: Bearer $SIMAMIA_TOKEN"
unset SIMAMIA_TOKEN
```

## Request conventions

- Send JSON with `Content-Type: application/json` for `POST` and `PATCH`.
- Send the API-issued token in `Authorization: Bearer <token>` on every business-data request.
- You may send `X-Request-ID` to correlate a call with your logs. The API creates a request ID if omitted and returns it in both the response header and `meta.request_id`.
- Monetary values are positive numeric amounts in Tanzanian shillings (TZS), unless the field is an amount already paid, which may be zero.
- Request bodies are limited to 1 MiB and must contain exactly one JSON object.
- Collection pages default to `page=1&page_size=20`; requested page sizes above 100 are capped at 100.
