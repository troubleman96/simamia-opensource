# Local account authentication

The open-source browser edition uses accounts stored by the Simamia Go API. People create an account with a name, Tanzania phone number, and password; there is no external identity-provider account or OAuth callback.

## Create an account

Send a `POST` request to `/auth/register`:

```http
POST /api/v1/auth/register
Content-Type: application/json

{"name":"Asha Mushi","phone":"+255 712 345 678","password":"choose-a-password","remember_me":true}
```

The API normalizes the phone to `+255` plus nine local digits, requires a name and a password of at least eight characters, then stores a salted PBKDF2 password hash in SQLite. Phone numbers must be unique. Successful registration creates a session and returns the account plus a random bearer token in `data.access_token`.

Use `POST /auth/login` with `phone`, `password`, and optional `remember_me` to sign in again. `remember_me: true` creates a 30-day session; otherwise the session expires after 12 hours. `POST /auth/logout` revokes the supplied session token. `GET /auth/me` returns the account for a valid session.

## Call protected endpoints

Send the returned token in the standard bearer header:

```http
Authorization: Bearer <local-session-token>
```

The API hashes session tokens before storing them, validates them locally, and uses the account's stable ID as `owner_sub` on its business records. It does not accept a phone number or password in place of a token.

## Status behavior

| Condition | Response |
| --- | --- |
| Missing, invalid, or expired session on a protected endpoint | `401 UNAUTHORIZED` |
| Duplicate phone during registration | `409 ACCOUNT_EXISTS` |
| Invalid registration fields | `422 VALIDATION_ERROR` |
| Local account endpoints used with the in-memory preview store | `503 AUTH_UNAVAILABLE` |

## Account isolation

List requests include only records whose `owner_sub` matches the authenticated local account ID. Reading, updating, or deleting another account's record returns `404`, just as if that ID did not exist. Business membership, invitations, staff roles, and shared-workspace access are not implemented yet.

## Browser CORS and security

The app sends cross-origin API requests from the configured browser origin. Set `CORS_ALLOWED_ORIGINS` to a comma-separated list of exact origins; use HTTPS for network access outside local development. The browser stores its bearer token in local storage when “Remember me” is selected and in session storage otherwise. Do not place tokens in URLs, source control, analytics events, or server logs.

The desktop edition remains different by design: Wails opens a per-device SQLite workspace directly and does not require a browser account or network connection. Browser users need the Go API for registration, sign-in, and server-backed business records. Password reset and account recovery flows are not currently implemented.
